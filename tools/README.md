# Сбор филиалов магазинов через Yandex Geosearch

Утилита `import_yandex_stores.py` формирует черновик филиалов для сетей из
`config/stores.json`. Для каждой сети она ищет филиалы в Санкт-Петербурге и
отдельно перепроверяет каждый адрес и координаты, уже записанные в исходном
файле.

## Запуск в PowerShell

Задайте API-ключ в текущем окне PowerShell, не добавляя его в код или JSON:

```powershell
$env:YANDEX_MAPS_API_KEY = "ваш-ключ"
& .\.venv\Scripts\python.exe .\tools\import_yandex_stores.py
```

Нужен доступ к HTTP API Поиска по организациям Яндекс Карт. Перед запуском
проверьте действующий тариф, квоты и условия использования в кабинете и
[документации API](https://yandex.ru/maps-api/docs/geosearch-api/index.html).

В черновике `theme` — список товарных категорий магазина. Соответствие
магазинов категориям хранится в `config/store_categories.json` и проверяется
по ключам `config/categories.json`. Исходные значения `theme` в `stores.json`
не меняются. Это приближённый ассортимент для синтетических данных, а не
гарантия наличия каждого товара в каждом филиале.

Дополнительные поисковые запросы для категорий, не покрытых существующими
сетями, задаются в `config/additional_store_searches.json`. Для каждого
запроса ограничено число новых магазинов и филиалов; в черновик добавляются
только филиалы с подтверждаемым адресом, координатами и однозначными часами.

## Результаты

- `config/stores_yandex_draft.json` — API-кандидаты в формате списка магазинов,
  пригодном для сравнения с текущей конфигурацией.
- `config/stores_manual_review.json` — причины ручной проверки кандидатов,
  найденные API сведения по каждому старому филиалу и сравнение расстояния
  между сохранёнными и найденными координатами.

`config/stores.json` скрипт не меняет. Все старые филиалы помечаются для
ручного просмотра: даже близкая точка API может оказаться другим магазином
в том же торговом центре. Для расписания используются структурированные часы
API, а если их нет — только однозначный текстовый график, покрывающий все дни
недели без перерывов. В таком случае в `open` и `close` записывается общий
интервал, когда магазин открыт во все дни. Круглосуточный график представляется
как `00:00`–`23:59`. Если нельзя получить безопасный общий интервал, филиал не
добавляется в черновик, а причина попадает в отчёт проверки.

При временных ошибках соединения и ответах HTTP 429/5xx запрос автоматически
повторяется до трёх раз с паузами. Если после этого API всё ещё недоступен,
импорт продолжает обработку остальных сетей и филиалов, записывает ошибку
в `stores_manual_review.json` и выводит предупреждение. Результаты такого
запуска будут неполными — повторите запуск после восстановления API.

Поиск API ранжирует наиболее подходящие запросу организации и не гарантирует
полный список филиалов сети. Поэтому отсутствие филиала в черновике не
доказывает, что такого магазина нет.
